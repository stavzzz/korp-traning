Замок на одну папку для Claude Code

  • Claude работает только внутри вашей папки и не выходит наружу
  • Установка за 5 минут: два файла, глобальные настройки не трогаем
  • Промпт для Claude Code, который всё сделает сам, и путь для ручной сборки
  • Проверка, что замок реально держит
Прогресс 0 / 0
01
Зачем нужен замок
🚨Реальный случай из курса. Claude Code, запущенный из домашней папки, получил задачу «почисти проект» и начал удалять файлы по всему компьютеру. Спасла только резервная копия. Второй раз такое не повторилось, потому что появился этот замок.
🔒Что делает замок. Claude видит и трогает только одну папку, которую вы ему выделили. Любой путь за её пределами блокируется: и в чтении файлов, и в командах терминала. Отдельно закрыты Рабочий стол, Документы, Загрузки и папки с ключами.
✅Что нужно от вас. Пять минут и два файла. Глобальные настройки Claude Code не трогаем: замок живёт внутри вашей рабочей папки и действует только когда Claude запущен из неё.
⚠Замок дополняет «Броню», а не заменяет её. Броня запрещает опасные команды вроде rm -rf и sudo. Замок запрещает выходить за границы папки. Ставьте обе защиты: они работают вместе.
02
Выбираем папку
📁Одна папка на все проекты. Заведите папку, например «VIBE CODING» в домашней директории, и складывайте все проекты внутрь. Claude всегда запускайте из неё или из папки проекта внутри неё. Какая папка открыта, та и становится границей.
Определиться с рабочей папкой
Правило простое: никогда не запускайте Claude из домашней папки целиком. Только из своей рабочей папки или из проекта внутри неё.
macOS: например /Users/имя/VIBE CODING
Windows: например {WIN_PATH_EXAMPLE}
Открыть эту папку в VS Code
File → Open Folder → выбрать именно рабочую папку. В VS Code граница замка совпадает с открытой папкой: открыли папку выше, граница уехала вверх.
03
Установка через Claude Code, самый простой путь
💡Три сообщения в Claude Code, и замок стоит. Первое сообщение: промпт-инструкция. Второе: содержимое settings.json. Третье: содержимое скрипта-охранника. Claude сам создаст файлы, подставит путь к папке и всё проверит. Выберите свою систему ниже.
📋 Промпт для macOS (в Claude Code)
Ты настраиваешь защиту для Claude Code на macOS: замок, который ограничивает Claude одной папкой. Сделай строго по шагам, ничего не придумывай. 1. Определи текущую рабочую папку проекта: это папка, из которой ты запущен. Назови её мне полным путём и дождись моего «да». 2. Создай в ней папку .claude/hooks/ если её нет. 3. Создай файл .claude/settings.json с содержимым, которое я пришлю следующим сообщением. Если файл уже есть, аккуратно объедини: добавь блоки permissions.deny и hooks, ничего из существующего не удаляй. 4. Создай файл .claude/hooks/scope-guard.sh с содержимым, которое я пришлю после settings.json. В строке ROOT= подставь полный путь к рабочей папке из шага 1. 5. Сделай файл исполняемым: chmod +x .claude/hooks/scope-guard.sh 6. Покажи мне итоговое содержимое обоих файлов и напомни: чтобы замок заработал, нужно перезапустить Claude Code из этой же папки. Не трогай ~/.claude/settings.json и никакие файлы за пределами рабочей папки.
macOS · файл 2 из 3: settings.json (отправить вторым сообщением)
{ "permissions": { "deny": [ "Read(~/.ssh/**)", "Read(~/.aws/**)", "Read(~/.gnupg/**)", "Read(~/Desktop/**)", "Read(~/Documents/**)", "Read(~/Downloads/**)", "Edit(~/Desktop/**)", "Edit(~/Documents/**)", "Edit(~/Downloads/**)", "Write(~/Desktop/**)", "Write(~/Documents/**)", "Write(~/Downloads/**)", "Bash(sudo *)", "Bash(cd ~*)", "Bash(cd /*)" ] }, "hooks": { "PreToolUse": [ { "matcher": "Bash|Read|Edit|Write|Glob|Grep|NotebookEdit", "hooks": [ { "type": "command", "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/scope-guard.sh", "timeout": 10, "statusMessage": "проверка границ папки" } ] } ] } }
macOS · файл 3 из 3: scope-guard.sh (отправить третьим сообщением)
#!/usr/bin/env bash # Ограничивает Claude Code одной папкой. # Любая попытка обратиться к пути вне ROOT блокируется. set -u # ========================================================== # ЗАМЕНИТЕ на свою папку (без слэша на конце) ROOT="$HOME/VIBE CODING" # ========================================================== input=$(cat) # Смотрим только на аргументы инструмента. # Служебные поля сессии (transcript_path, cwd) отбрасываем — там всегда есть # путь к домашней папке, и без этого шага срабатывал бы ложный запрет. payload=${input#*'"tool_input"'} # Вырезаем из текста все упоминания разрешённой папки. # Всё, что осталось и указывает в домашнюю папку — это выход за границу. rest=${payload//"$ROOT"/} deny() { printf '{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"Доступ запрещён: путь вне разрешённой папки.\\nРазрешено только: %s"}}' "$ROOT" exit 0 } case "$rest" in *"$HOME"*) deny ;; *'/Users/'*) deny ;; *'~/'*) deny ;; *'$HOME'*) deny ;; esac # Попытки выйти наверх относительным путём или уйти в корень диска: # cd .., cd ../.., cd /, cd /etc, а также ../ в любом аргументе. case "$rest" in *'cd ..'*|*'cd /'*|*'cd "/'*|*"cd '/"*|*'../'*) deny ;; esac exit 0
macOS: отправить три сообщения в Claude Code и дождаться отчёта
Claude покажет содержимое созданных файлов. Проверьте, что в строке ROOT= стоит путь именно к вашей рабочей папке, без слэша на конце.
📋 Промпт для Windows (в Claude Code)
Ты настраиваешь защиту для Claude Code на Windows: замок, который ограничивает Claude одной папкой. Сделай строго по шагам, ничего не придумывай. 1. Определи текущую рабочую папку проекта: это папка, из которой ты запущен. Назови её мне полным путём и дождись моего «да». 2. Создай в ней папку .claude\hooks\ если её нет. 3. Создай файл .claude\settings.json с содержимым, которое я пришлю следующим сообщением. Если файл уже есть, аккуратно объедини: добавь блоки permissions.deny и hooks, ничего из существующего не удаляй. 4. Создай файл .claude\hooks\scope-guard.ps1 с содержимым, которое я пришлю после settings.json. В строке $Root = подставь полный путь к рабочей папке из шага 1. 5. Покажи мне итоговое содержимое обоих файлов и напомни: чтобы замок заработал, нужно перезапустить Claude Code из этой же папки. Не трогай %USERPROFILE%\.claude\settings.json и никакие файлы за пределами рабочей папки.
Windows · файл 2 из 3: settings.json (отправить вторым сообщением)
{ "permissions": { "deny": [ "Read(~/.ssh/**)", "Read(~/.aws/**)", "Read(~/Desktop/**)", "Read(~/Documents/**)", "Read(~/Downloads/**)", "Edit(~/Desktop/**)", "Edit(~/Documents/**)", "Edit(~/Downloads/**)", "Write(~/Desktop/**)", "Write(~/Documents/**)", "Write(~/Downloads/**)", "Bash(cd ~*)", "Bash(cd /*)" ] }, "hooks": { "PreToolUse": [ { "matcher": "Bash|Read|Edit|Write|Glob|Grep|NotebookEdit", "hooks": [ { "type": "command", "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"$CLAUDE_PROJECT_DIR/.claude/hooks/scope-guard.ps1\"", "timeout": 10, "statusMessage": "проверка границ папки" } ] } ] } }
Windows · файл 3 из 3: scope-guard.ps1 (отправить третьим сообщением)
# Ограничивает Claude Code одной папкой. # Любая попытка обратиться к пути вне $Root блокируется. # ========================================================== # ЗАМЕНИТЕ на свою папку (без слэша на конце) $Root = Join-Path $env:USERPROFILE 'VIBE CODING' # ========================================================== $raw = [Console]::In.ReadToEnd() # Смотрим только на аргументы инструмента. # Служебные поля сессии отбрасываем — там всегда есть путь к профилю # пользователя, и без этого шага срабатывал бы ложный запрет. $i = $raw.IndexOf('"tool_input"') $payload = if ($i -ge 0) { $raw.Substring($i) } else { $raw } # Вырезаем упоминания разрешённой папки в обоих видах: # как есть и с экранированными слэшами (так путь выглядит внутри JSON). $rest = $payload.Replace($Root, '').Replace($Root.Replace('\', '\\'), '') $needles = @( 'cd ..', 'cd /', 'cd \', 'cd "/', 'cd "\', '../', '..\', $env:USERPROFILE, $env:USERPROFILE.Replace('\', '\\'), 'C:\Users\', 'C:\\Users\\', '~/', '~\' ) foreach ($n in $needles) { if ($rest.Contains($n)) { $reason = "Доступ запрещён: путь вне разрешённой папки.`nРазрешено только: $Root" $out = @{ hookSpecificOutput = @{ hookEventName = 'PreToolUse' permissionDecision = 'deny' permissionDecisionReason = $reason } } $out | ConvertTo-Json -Depth 5 -Compress exit 0 } } exit 0
Windows: отправить три сообщения в Claude Code и дождаться отчёта
Claude покажет содержимое созданных файлов. Проверьте, что в строке $Root = стоит путь именно к вашей рабочей папке, без слэша на конце.
04
Установка руками, если Claude Code ещё не настроен
🛠Тот же результат, только вручную. Нужны два файла внутри рабочей папки: настройки и скрипт-охранник. Содержимое берите из блоков выше.
Создать папку .claude/hooks внутри рабочей папки
macOS: в Finder скрытые папки показываются по Cmd + Shift + точка. Либо в Терминале одной командой:
mkdir -p ~/"VIBE CODING/.claude/hooks"
Создать файл .claude/settings.json
Содержимое: блок «settings.json» для вашей системы из шага 03. Если файл уже существует, добавьте в него блоки permissions.deny и hooks, ничего не удаляя.
Создать файл-охранник и вписать свою папку
macOS: .claude/hooks/scope-guard.sh, в строке ROOT= укажите свою папку.
Windows: {WIN_HOOK_PATH}, в строке $Root = укажите свою папку.
Слэша на конце быть не должно.
macOS: разрешить запуск скрипта
В Терминале одна команда:
chmod +x ~/"VIBE CODING/.claude/hooks/scope-guard.sh"
⚠Windows и политика запуска скриптов. Команда в settings.json уже содержит -ExecutionPolicy Bypass, поэтому менять системную политику PowerShell не нужно. Если Windows всё же ругается, откройте PowerShell от администратора и выполните: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
05
Проверяем, что замок работает
Перезапустить Claude Code из рабочей папки
Настройки читаются при старте. Закройте Claude Code и запустите заново. macOS, в Терминале:
cd ~/"VIBE CODING" && claude
🪟Windows, в PowerShell:
cd "$env:USERPROFILE\VIBE CODING"; claude
Попросить Claude прочитать файл вне папки
Напишите Claude: «прочитай файл ~/Desktop/test.txt». Правильный ответ: «Доступ запрещён: путь вне разрешённой папки». Если файл прочитался, проверьте путь в ROOT или $Root и перезапустите Claude.
Попросить Claude сделать что-то внутри папки
Например: «покажи список файлов в этой папке». Должно работать как обычно. Замок мешает только выходить наружу.
💡На будущее:
• Все новые проекты создавайте внутри рабочей папки: замок покроет их автоматически.
• Замок это защита на уровне Claude Code, а не операционной системы. Он спасает от ошибок агента, но не заменяет резервные копии.
• Раз в месяц повторяйте тест из этого раздела: обновления Claude Code иногда меняют формат настроек.
