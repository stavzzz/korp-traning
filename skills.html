01
Что такое skill за 5 минут
📖 Самый частый ступор: люди ищут «skill» в настройках Claude как кнопку. На самом деле skill — это папка с файлами на вашем компьютере, которую вы загружаете в Claude через интерфейс. Усвоили это — половина пути пройдена.
Skill для Claude
Папка с инструкциями, которая учит Claude решать конкретную повторяющуюся задачу. Один раз описали свой процесс — потом вызываете skill в чате через /, и Claude применяет вашу методику. Объяснять каждый раз не нужно.
📌 Без skill каждый раз приходится диктовать критерии оценки и формат вывода. Со skill — один раз настроили, потом вызываете через /имя-skill в нужном чате, и Claude применяет ваши правила.
SKILL.md
Главный файл skill. Регистр в имени важен — ровно SKILL.md, не skill.md. Это обычный Markdown, в начале которого — служебная YAML-шапка, а ниже — инструкции на человеческом языке.
📌 YAML-шапка нужна Claude, чтобы понять, что это за skill и для каких задач он подходит. Тело — это инструкции, по которым Claude работает, когда вы вызвали skill через /.
Progressive Disclosure
Архитектурный приём Claude: skill подгружается в память моделью «слоями». Сначала читается только YAML-шапка (всегда). Если задача подходит — подгружается тело SKILL.md. Если нужны детали — Claude сам открывает файлы из вложенных папок.
📌 Аналогия: библиотека. На обложке книги (YAML) — название и аннотация. Внутри (SKILL.md) — основной текст. В приложениях (references/) — справочные таблицы. Не нужно читать всё сразу — Claude читает только то, что относится к делу.

Минимальная папка skill выглядит так:

📁 my-skill-name/ └── 📄 SKILL.md # один обязательный файл — больше ничего не нужно

Всё. Этого достаточно, чтобы Claude подхватил ваш skill. scripts/, assets/, references/ — опциональные папки, добавляются только если они реально нужны под задачу. На первом skill начинаем с минимума.

⚡ Хорошая новость: папку SKILL.md руками собирать не нужно. В Claude встроен помощник /skill-creator, который сделает её за вас в формате диалога. Подробности — в разделе 03.
Понять: skill — это папка, а не настройка в интерфейсе
Не ищите кнопку «создать skill» в чате. Папка создаётся через /skill-creator, потом упаковывается в zip и загружается в Claude через настройки. После загрузки skill вызывается в любом чате через /имя-skill.
Открыть Claude и найти меню skills
В Claude.ai откройте Settings → Capabilities → Skills. Там лежат уже встроенные от Anthropic (docx, pdf, pptx, xlsx, skill-creator). Они нам не нужны как отправная точка, но посмотреть, как описаны их description — полезно. Это эталон формулировок.
Сформулировать одной фразой задачу для своего будущего skill
Шаблон: «Skill, который [глагол] [объект] [по какому правилу]. Применяется для [тип задач]».
Если задача не укладывается в одну фразу — её нужно сузить, иначе skill получится размытым.
02
Анатомия SKILL.md — что внутри созданного skill
🧬 /skill-creator создаст файл SKILL.md за вас. Но открыть его и понять, что внутри — критически важно: иначе невозможно оценить качество результата и доработать. Это не «чёрный ящик», а текстовый файл, который можно прочитать.

Любой SKILL.md состоит из двух частей: YAML-шапка (между ---) и тело инструкций на Markdown под ней. Шапка — «визитная карточка» для Claude: имя skill и для каких задач он подходит. По телу skill — Claude понимает, как именно решать задачу, когда вы вызвали skill через /.

Минимальный рабочий SKILL.md выглядит так:

---
name: email-improver
description: Улучшает деловые письма по корпоративным правилам:
  делает короче, убирает воду, расставляет акценты.
  Использовать, когда пользователь просит «улучши письмо»,
  «перепиши деловое письмо», «сделай короче и яснее»,
  «вычитай мой email».
---

# Email Improver

## Когда применять
Подключайся, когда пользователь даёт текст письма
и просит его улучшить.

## Как работать
1. Прочитай исходный текст
2. Найди слабые места: вода, размытые формулировки, длинноты
3. Перепиши: короче, чётче, с явным целевым действием
4. Покажи «до» и «после» с пояснениями
🔑 Два обязательных поля в шапке: name (имя skill, в kebab-case) и description (что делает + для каких задач подходит). Всё остальное — опционально.
Формула description
[Что делает] + [Для каких задач подходит] + [Примеры типичных запросов]. Все три части помогают Claude правильно применить skill, когда вы вызвали его через /. Без них skill будет работать наугад.
📌 Лимит: 1024 символа. XML-теги (< или >) запрещены. Слова «claude» и «anthropic» в имени тоже запрещены — зарезервированы.

Сравните: правильное и плохое описание

✓ Правильно
Конкретное действие, ясно для каких задач подходит, 3+ примеров запросов.

Улучшает деловые письма по корпоративным правилам: делает короче, убирает воду, расставляет акценты. Использовать, когда пользователь просит «улучши письмо», «перепиши деловое письмо», «сделай короче и яснее».
✗ Не сработает
Размыто, нет примеров запросов, не понятно, чем этот skill лучше прямого промпта.

Помогает с письмами.

Email-ассистент.

Имя папки и файла — отдельная боль:

✓ Правильно
email-improver
meeting-notes-formatter
document-summarizer

kebab-case: всё строчными, через дефис, без пробелов и подчёркиваний.
✗ Сломается
Email Improver — пробелы
email_improver — подчёркивания
EmailImprover — CamelCase
skill.md или SKILL.MD — регистр главного файла
⚠️ Имя папки и значение поля name в YAML-шапке должны совпадать символ в символ. Несовпадение — частая причина «skill не загружается». /skill-creator обычно делает это правильно, но при ручной правке можно сбить.
Понять формулу description
Когда /skill-creator предложит вам description — вы должны уметь его прочитать и оценить: есть ли в нём все три части (что делает + для каких задач подходит + примеры запросов). Если нет — попросить переписать.
Понять, как skill вызывается в разговоре
Skill вызывается только вручную: введите / в чате, выберите нужный skill из списка. Сам по себе он не подключается — Claude не сканирует ваши сообщения и не угадывает, какой skill применить. description в YAML-шапке нужен для другого: когда вы вызвали skill через /, Claude читает description, чтобы понять, как именно применить skill к вашему запросу.
Понять правила именования
2–4 слова, через дефис, всё строчными. Глагол + объект работают лучше всего: email-improver, document-summarizer. Запрещены слова claude и anthropic. /skill-creator обычно соблюдает эти правила, но проверяйте.
03
Сборка skill через /skill-creator
🛠️ Это hands-on часть. Здесь вы собираете свой skill через диалог со встроенным помощником /skill-creator. Никакого ручного редактирования файлов, никакой работы с zip — всё через чат. На выходе — готовая папка skill, которую Claude сам упакует.

Общая логика процесса:

# 1. Подготовка контекста (опционально) Свои материалы → конвертация в Markdown → .md файлы # 2. Сборка skill через диалог Чат с Claude → /skill-creator → Диалог уточнений # 3. Получение готового skill SKILL.md + assets/ → .zip → Готов к загрузке
Подготовить материалы для skill (опционально)
Если у skill будет своя «база знаний» — методички, инструкции, шаблоны — лучше иметь их в формате Markdown. /skill-creator работает с Markdown точнее, чем с PDF (PDF съедает много токенов на изображения страниц).

Конвертация PDF → Markdown делается отдельным skill (см. раздел 07, кейс pdf-to-markdown) или вручную через Preview/Word.
Открыть новый чат и вызвать /skill-creator
В поле ввода введите / — появится список доступных skills. Выберите skill-creator. Это встроенный skill от Anthropic, доступен в любом аккаунте.
Описать задачу и приложить материалы
Прикрепите ваши .md-файлы (контекст для skill) и опишите задачу одной-двумя фразами:

«Создай skill [название], который [что делает] на основе приложенных материалов. Применяется для [тип задач]».
Пройти диалог уточнения
/skill-creator начнёт задавать уточняющие вопросы: какое имя, для каких задач, какая внутренняя структура. Отвечайте честно и подробно — чем точнее, тем лучше результат.

Если предложенный description выглядит размытым — попросите переписать с конкретными примерами запросов. Если структура слишком сложная — попросите упростить. Это диалог, а не одностороннее ТЗ.
Проверить результат глазами
В конце диалога /skill-creator покажет финальную структуру: SKILL.md, при необходимости references/ и assets/. Откройте SKILL.md и пройдитесь глазами — формула description, имя в kebab-case, понятное тело инструкций. Если что-то не так — попросите доработать.
Получить готовый zip
Когда всё устраивает — попросите /skill-creator экспортировать skill в zip. Полученный архив можно загружать в свой Claude (Settings → Capabilities → Skills → Upload) и раздавать команде.
04
Безопасность — что можно и нельзя загружать в skill
🛑 Главное правило: обезличивание выполняется ДО загрузки документа в любой ИИ-инструмент. И программными методами, без участия нейросетей. «Claude, обезличь этот документ» — недопустимая формулировка. Нейросеть для обезличивания не используется никогда.

Почему именно так: любая загрузка документа в облачный ИИ — это передача данных за периметр. Если документ не обезличен, утечка уже произошла, дальнейший «обработай» ничего не меняет. Поэтому обезличивание — отдельный этап, выполняемый локальными инструментами под вашим контролем.

Что считается чувствительными данными
ФИО сотрудников и контрагентов, ИНН, паспортные данные, телефоны, адреса. Названия компаний-партнёров. Номера и суммы договоров. Реквизиты счетов. Любые персональные данные клиентов.
📌 Все эти типы данных перед загрузкой в Claude / ChatGPT / любой облачный ИИ заменяются на плейсхолдеры: [ФИО], [КОМПАНИЯ], [СУММА], [АДРЕС], [ДОГОВОР №].

Четыре рабочих метода программного обезличивания:

📝
Word / Excel + макрос
Самый доступный метод. Ctrl+H для замены, регулярные выражения для типовых форматов (ИНН, телефон, паспорт). Запись макроса один раз — потом запуск кнопкой.
🐍
Python-скрипт с regex
Для пакетной обработки. Библиотека re + список регулярок под ИНН, телефон, дату, номер договора. Запуск из терминала. Работает офлайн.
🔐
Офлайн-утилиты
Microsoft Presidio (open-source), отечественные DLP-решения. Ставятся локально, ничего не отправляют наружу. Уровень — IT-служба.
👁️
Ручная проверка
После любого автоматического обезличивания — обязательный визуальный контроль. Скрипты не ловят 100%: неформатные ФИО, опечатки, имена в свободном тексте.
⚠️ Что НЕ должно попадать в файлы skill (ни в SKILL.md, ни в assets, ни в references): реальные ФИО, реальные ИНН, названия контрагентов, суммы конкретных договоров, любые пароли / API-ключи / токены доступа. Skill — это публикуемый артефакт, всё внутри него считайте потенциально открытым.
Обезличить материалы программно перед загрузкой
Пройдитесь по каждому файлу любым из четырёх методов выше. Замените все ФИО / контрагентов / суммы / адреса / номера на плейсхолдеры. После авто-обработки — глазами просмотрите файл целиком, не доверяйте регуляркам на 100%.
Убедиться, что в материалах нет секретов
Никаких паролей, API-ключей, токенов, ссылок на внутренние сервисы. Если в исходниках есть — удалить или заменить на плейсхолдеры до загрузки. Skill потом увидят коллеги, и эти данные тоже.
Прописать в SKILL.md правила работы с данными
В разделе «Ограничения» вашего SKILL.md явно укажите: «работать только с обезличенными документами», «реальные ФИО и реквизиты — никогда не подставлять», «при сомнениях — запросить обезличенную версию у пользователя». Это защита от того, что коллега загрузит реальный документ по привычке.
Согласовать с СБ перед работой с реальными корпоративными данными
Skill, обкатанный на синтетике или учебных материалах — это учебный артефакт. Использование на реальных рабочих документах — отдельный шаг с участием службы безопасности компании. Особенно для документов под NDA, договоров с контрагентами, персональных данных.
05
Тестирование — проверяем, что skill реально работает
🔍 Skill проверяется на трёх уровнях: вызов (виден ли в списке после /, правильно ли назван), функционал (корректен ли результат) и сравнение «до/после» (реально ли быстрее, чем без skill). Без всех трёх — skill считается неготовым.

Три уровня проверки:

🎯
Вызов
Введите / — skill должен появиться в списке. Вызовите его, подайте профильную задачу. Должен корректно отработать.
⚙️
Функционал
Прогоняете одну реальную задачу. Результат должен быть в нужном формате, без галлюцинаций, готов к использованию.
📊
До / После
Сравниваете время и качество с тем же запросом без skill. Если выигрыш меньше 2x — skill нужно дорабатывать.
👥
Внешний прогон
Даёте skill коллеге, не объясняя. Если он не сможет получить результат с одного-двух запросов — описание skill нужно уточнять.

Пример теста для skill email-improver:

✓ Корректно работает
После вызова /email-improver и подачи задачи:

«Улучши это письмо: [текст]»

«Перепиши деловой email короче»

«Вычитай этот email на воду»

→ skill применяет правила, возвращает улучшенную версию.
✗ Должен отказать
После вызова /email-improver и подачи постороннего:

«Напиши код на Python»

«Переведи текст на английский»

«Сделай презентацию»

→ skill должен сказать, что задача не его профиля.
Загрузить .zip в Claude.ai
Settings → Capabilities → Skills → Upload. Если skill не загрузился — частые причины: имя файла не SKILL.md (регистр), архивирована не папка а её содержимое, в YAML-шапке нет тройных дефисов или они с пробелами.
Вызвать skill через / — проверить, что он есть в списке
Откройте новый чат в Claude. Введите / — в выпадающем списке должен появиться ваш skill с правильным именем и описанием. Если его нет или название неправильное — проверьте YAML-шапку SKILL.md.
Подать постороннюю задачу — проверить, что skill отказывает
Вызовите skill через / и подайте задачу не из его профиля (для email-improver — например, «напиши код»). Skill должен честно сказать, что это не его задача. Если он берётся выполнять что попало — описание в SKILL.md размыто, нужно конкретизировать.
Прогнать одну реальную задачу
Возьмите свой реальный кейс и пройдите процесс целиком. Проверьте: формат правильный, нужные данные подставлены, результат на 80%+ готов к использованию. Если да — skill рабочий.
Сравнить с работой без skill
Выключите skill и решите ту же задачу обычным промптом. Сравните: сколько сообщений ушло, сколько раз пришлось править, насколько результат соответствует нужному формату. Если выигрыш по времени минимум 2x — skill оправдывает себя. Если меньше — что-то в инструкциях упущено.
06
Когда skill не нужен — защита от оверинжиниринга
🚧 Skill — это инструмент стандартизации повторяющегося процесса. Если процесса нет, или он разовый, или нужен только вам одному — skill будет лишней работой. Чек-лист ниже помогает не тащить «всё в skill» по инерции.

Простое правило выбора инструмента под задачу:

💬
Разовая задача
Один раз нужно собрать письмо или разобрать документ — обычный промпт в чате. Skill не нужен.
📂
Контекст для одного
Регулярная работа в одном тематическом контексте — системный промпт в Claude Project. Skill избыточен.
🛠️
Процесс для команды
Повторяющийся процесс, по которому работает несколько человек, нужен единый стандарт результата — skill подходит идеально.
🤖
Многошаговая автоматизация
Нужны интеграции с почтой / календарём / БД, проактивность, работа в фоне — это уже агент, не skill.

Зелёный сигнал на сборку skill — выполняются все четыре условия:

(1) задача повторяется не реже раза в неделю; (2) у задачи есть устойчивая структура входа и выхода; (3) ей пользуются хотя бы два человека или планируют — для масштабирования; (4) результат должен быть в стандартном формате. Если хотя бы одно условие не выполняется — пересмотрите, может быть достаточно промпта или системного промпта проекта.

✓ Хорошая практика: сначала решите задачу 5-10 раз обычным промптом, найдите устойчивую формулу, и только потом оборачивайте её в skill. Skill, написанный «теоретически», обычно проигрывает skill, выкристаллизованному из практики.

Что внутри prompt-maker — четырёхуровневая методика:

01
База — структура промпта
Роль (опционально) + Контекст + Ожидание. От чьего лица отвечать, о чём идёт речь, в каком виде нужен результат. Минимально достаточный набор для большинства задач.
02
Усилители — продвинутые техники
Разделители, пошаговые инструкции, обучение на примерах (few-shot), цепочка рассуждений (chain-of-thought), прямой вопрос к LLM. Применяются, когда базы недостаточно: задача сложная, нужен конкретный формат, требуется логическое рассуждение.
03
Защита — от галлюцинаций
Запрет додумывать факты, отделение фактов от предположений, привязка к источнику, самопроверка, проверяемый формат. Применяется в критичных задачах: юриспруденция, финансы, договоры — везде, где цена ошибки высокая.
04
Эмоциональный контекст — EmotionPrompt
«Это очень важно для моей работы», «постарайся качественно — от этого зависит результат», «я ценю твою помощь». Эмпирический прирост точности 8-10% (исследование EmotionPrompt, Microsoft Research). Используется умеренно — на критичных задачах, не на каждом запросе.
🎯 Почему именно такая иерархия: у вас появляется чёткий путь от простого к сложному. На большинстве задач хватит базы. На сложных — добавятся усилители. На критичных — подключится защита. Эмоциональный контекст — финальный штрих для самых важных запросов.
