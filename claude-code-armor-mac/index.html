Дисклеймер. Эта защита построена строго по официальным рекомендациям Anthropic (разработчик Claude Code) — риск сведён к уровню, который сам производитель считает лучшей практикой. Но стопроцентной гарантии нет — этого не обещает и сама Anthropic в своей документации. Обязательно держите резервную копию важных файлов (раздел 04) независимо от того, настроена эта защита или нет — это ваша последняя страховка.

00
Зачем эта защита
⚠️
Повод. Был случай: Claude Code выполнил команду D=$(pwd); cd /; rm -rf "$(dirname "$D")" и удалил домашнюю папку. Строковые фильтры не сработали — цель вычислялась «на лету». Значит, защищаться нужно не от конкретных строк, а от класса операций.
🛡️
Три слоя. 1) Песочница ядра ОС — не даёт трогать файлы вне папки проекта. 2) Инспектор команд — блокирует опасные команды до запуска. 3) Чёрный список — грубая, но независимая подстраховка. Плюс бэкапы.
💬
Простыми словами. Представьте, что Claude Code работает в закрытой комнате — папке вашего проекта. Внутри неё он может свободно создавать, менять и удалять файлы. А вот дотянуться до чего-то за её пределами — до других папок, документов, фото — физически не может, даже если ошибётся в команде. Это не «просьба не делать так», а настоящая стена, которую держит сама операционная система.
⚡
Скорость не страдает. Внутри песочницы обычные команды выполняются без лишних подтверждений — границу держит ядро, а не вопросы.
✅
Честный ответ на вопрос «а что, если что-то пойдёт не так». У Claude Code уже есть встроенная базовая защита: даже без всей этой настройки он всегда переспрашивает перед буквальной командой «удалить всё в домашней папке». Но именно поэтому был реальный инцидент — команда из шага «Повод» выше не содержит эти слова напрямую, путь вычисляется на лету через переменные, и базовая защита её не узнаёт. Три слоя выше закрывают ровно этот пробел — не «на всякий случай», а под конкретный, реально случившийся сценарий.
01
Подготовка
Claude Code нужно запускать из вложенной папки проекта, не из домашней. Создайте рабочую папку и откройте её в VS Code:
mkdir -p ~/dev/projects/my-app && cd ~/dev/projects/my-app
Рабочая папка создана, проект открыт из неё
VS Code и расширение Claude Code установлены и залогинены
Инспектору нужен jq (парсер JSON). Установите Homebrew (brew.sh), затем поставьте jq:
brew install jq
jq установлен
Проверка: команда jq --version печатает версию.
💬
Зачем jq? Это маленькая вспомогательная программа. Она нужна инспектору команд (следующий шаг), чтобы «прочитать» вашу команду перед тем, как пропустить её или заблокировать. Сам по себе jq ничего не защищает — но без него инспектор не сможет работать.
02
Установка защиты
Откройте Claude Code в VS Code и отправьте один промпт. Claude сам сделает резервную копию настроек, создаст все файлы защиты и проверит их — ничего разрушительного не выполняя.
💬
Как это работает простыми словами. Ниже — один большой текст (промпт). Вам не нужно ничего писать руками или разбираться, что означает код внутри. Просто скопируйте промпт целиком и отправьте его Claude Code как обычное сообщение — Claude сам прочитает его и выполнит все шаги по порядку.

03
Проверка, что защита включена
Три панели в Claude Code и два безопасных теста. Ничего не удаляется.
💬
Что такое эти панели. /sandbox, /hooks и /permissions — это команды, которые вы просто вводите в чат Claude Code, как обычное сообщение. Каждая открывает свой экран с настройками. Так вы своими глазами убедитесь, что защита действительно включена, а не просто «должна была» включиться.
/sandbox → вкладка Config: enabled = true
/hooks → PreToolUse → Bash: виден bash-guard.sh
/permissions → в списке deny есть sudo, rm -rf /, dd и другие
🚨
Прочитайте перед тестами — это важно. Оба теста ниже безопасны на 100%, если делать их ровно так, как написано: скопировать команду целиком и не менять в ней ни символа. Главное правило безопасности: никогда не проверяйте защиту, вручную набирая настоящую разрушительную команду («а вдруг она правда всё удалит?») — не нужно самому пытаться сделать что-то похожее на rm -rf по своим папкам «ради теста». Если что-то пойдёт не так при ручном эксперименте — это будет уже не тест, а настоящее удаление, и защита тут ни при чём. Ниже — только готовые, проверенные команды.
Тест инспектора. Вставьте в обычный терминал (не в Claude). Ожидание — сообщение «ЗАБЛОКИРОВАНО» и exit=2:
💬
Почему это безопасно, хотя внутри написано rm -rf. Команда с rm -rf здесь — это просто кусок текста в кавычках, «упакованный» внутрь JSON. Скрипт-инспектор её не запускает, а только читает и анализирует как текст, — точно так же, как вы можете прочитать вслух слово «огонь», не устроив пожар. Ничего не удаляется, даже если бы инспектора вообще не существовало.
echo '{"tool_input":{"command":"D=$(pwd); cd /; rm -rf \"$(dirname \"$D\")\""},"cwd":"'"$PWD"'"}' | ~/.claude/hooks/bash-guard.sh; echo "exit=$?"
Тест инспектора пройден (exit=2)
Тест ядра. Попросите Claude Code выполнить команду ниже — ядро ОС должно ответить «Operation not permitted». В обычном терминале файл создастся: это нормально, терминал не в песочнице.
💬
Худший исход этого теста — не катастрофа. Команда пытается создать один крошечный пустой файл в домашней папке — она ничего не удаляет и не перезаписывает. Если песочница настроена верно, вы увидите отказ. Если что-то пошло не так и файл всё же создался — просто удалите его вручную, это не повод для паники.
touch "$HOME/guard-probe.txt"

Файл 1 из 3 — «инспектор команд». Это и есть тот самый скрипт, который на лету проверяет каждую команду Claude Code и блокирует опасные ещё до запуска. Кладётся в ~/.claude/hooks/, и его нужно сделать исполняемым командой chmod +x — иначе система откажется его запускать.

Файл 2 из 3 — главные настройки. Это основной конфигурационный файл Claude Code. Здесь включается сама песочница (стена вокруг папки проекта), подключается инспектор-скрипт из файла выше, и задаётся чёрный список команд, которые Claude Code не выполнит никогда, даже если его прямо попросить. Именно эти три вещи вместе и образуют защиту.

Файл 3 из 3 — правила поведения. Это не техническая защита, а простой текстовый файл с правилами, которые Claude Code читает и старается соблюдать в разговоре — как памятка для честного помощника. В отличие от двух файлов выше, он ничего физически не блокирует: настоящий барьер держат песочница и инспектор. Этот файл — дополнительный слой здравого смысла, а не стена.
~/.claude/CLAUDE.md
# Глобальные правила безопасности Claude Code ## Откуда запускать - НИКОГДА не запускать `claude` из домашней папки ($HOME) или из каталога первого уровня под ней. - Только из вложенной проектной директории: `~/dev/projects/<проект>`. - Правильный запуск: `cd ~/dev/projects/my-app && claude` - Нужен соседний каталог — `--add-dir <путь>`, а не запуск уровнем выше. ## Разрушительные операции - `rm -r`/`rm -rf` — только по литеральным относительным путям внутри проекта. Никогда по переменным ("$DIR"), подстановкам ($(...)), ~, ., .. , * или абсолютным путям вне проекта. - Никакого sudo. Требуется sudo — остановись и попроси человека. - Никаких `curl ... | sh`, `git clean -x*`, `find ... -delete`, записи в /dev/disk*. - Перед массовой операцией — перечисли, что будет затронуто, и жди подтверждения. ## Защитные слои (не отключать) 1. Песочница ядра ОС: sandbox.enabled в ~/.claude/settings.json. 2. PreToolUse-хук: ~/.claude/hooks/bash-guard.sh (лог: ~/.claude/bash-guard.log). 3. permissions.deny в ~/.claude/settings.json. 4. Бэкапы: Time Machine / снапшоты / git.
