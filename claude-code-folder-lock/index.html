Что это за замок и зачем он нужен
Claude Code — это помощник, который умеет сам создавать, менять и удалять файлы, а также запускать команды в терминале. Это его сила и его же опасность. По умолчанию он видит гораздо больше, чем один ваш проект: домашнюю папку, Рабочий стол, Документы, Загрузки. У нас на курсе он однажды начал чистить файлы по всему компьютеру. Спасла резервная копия, а потом появился этот замок.
Что делает замок. Вы выбираете одну рабочую папку и объявляете её единственной разрешённой территорией. Любая попытка прочитать, изменить или удалить что-то за её пределами отклоняется. Не «спрашивается разрешение», а именно отклоняется.
💡
Аналогия: вы не запираете от помощника отдельные ящики. Вы выдаёте ему одну комнату и забираете ключи от остальной квартиры.
Из чего состоит замок: два маленьких файла.
• settings.json — список запретов. Прямо перечисляет места, куда ходить нельзя: ключи доступа, Рабочий стол, Документы, Загрузки. Плюс запрещает команды повышения прав.
• scope-guard — сторож. Вызывается перед каждым действием Claude Code, смотрит, что тот собирается сделать, и ищет в этом путь за пределами разрешённой папки. Нашёл — отклоняет. Не нашёл — молча пропускает.
Сторож не читает ваши файлы и никуда ничего не отправляет. Работает без интернета, занимается только одним: сравнивает пути. Внутри около тридцати строк текста, их можно прочитать глазами.
Честно о границах. Это защита на уровне самого Claude Code, а не изоляция уровня операционной системы. Тот, у кого есть доступ к файлам настроек, может замок снять или изменить. Замок надёжно блокирует обращения к путям вне вашей папки: и в файловых операциях, и внутри команд терминала. Но внутри разрешённой папки Claude по-прежнему полноправен: может менять и удалять файлы.
⚠️
Замок не отменяет резервные копии. Важное держите в облаке или в git.
🛤
У вас два пути, выбирайте любой:

• Путь 2, через Claude Code: скачать архив и отдать его Claude Code с готовым промптом, он всё разложит сам. Разделы 01, 02 и 05.

01
Выберите папку, в которой будете работать
Заведите одну папку под все свои проекты и работайте только в ней. Название любое, но лучше без русских букв — так меньше сюрпризов с путями. В инструкции для примера используется папка VIBE CODING в домашней папке.
🚫
Не выбирайте домашнюю папку целиком и не выбирайте Рабочий стол, Документы или Загрузки. Смысл замка в том, чтобы разрешённая территория была узкой. Если разрешить всё — защищать нечего.
Папка выбрана, её точное название записано
Название понадобится дальше: его нужно будет вписать в один файл. Проверьте регистр букв и пробелы.

03
Установка на MacmacOS
🎯
Что получится в итоге. Внутри вашей рабочей папки появится скрытая папка .claude, а в ней ещё одна папка hooks. Всего две новые папки, одна внутри другой, и два файла из архива. Ниже пример для рабочей папки VIBE CODING, у вас будет своё название.
как должно выглядеть в итоге
VIBE CODING/ ← ваша рабочая папка, уже есть └── .claude/ ← папка 1, создаёте вы ├── settings.json ← файл из архива └── hooks/ ← папка 2, создаёте вы, внутри .claude └── scope-guard.sh ← файл из архива
Шаг 1. Создайте две папки. Откройте свою рабочую папку в VS Code: File → Open Folder. Слева в дереве файлов нажмите правой кнопкой на пустое место → New Folder → назовите .claude (с точкой в начале). Затем правой кнопкой на созданную .claude → New Folder → назовите hooks.
💡
В VS Code папки с точкой видны сразу, ничего включать не нужно. В Finder они спрятаны: показать можно сочетанием Cmd + Shift + точка.
Папки .claude и .claude/hooks созданы
Проверка в VS Code: в дереве слева видно .claude, а внутри неё hooks.
Шаг 2. Перетащите два файла из архива. Откройте распакованную папку архива в Finder и перетащите файлы прямо в дерево VS Code:
куда что положить
settings.json → в папку .claude scope-guard.sh → в папку .claude/hooks
Оба файла лежат на своих местах
Проверка: settings.json лежит рядом с папкой hooks, а scope-guard.sh внутри hooks. Файл README.txt никуда класть не нужно.
Шаг 3. Впишите свою папку в файл-сторож. В VS Code откройте scope-guard.sh (кликните по нему в дереве). В начале файла найдите строку, которая начинается на ROOT=. Замените текст между кавычками на путь к вашей рабочей папке.
пример: было и стало
Было (так лежит в архиве): ROOT="$HOME/VIBE CODING" Стало, если ваша папка называется «Мои проекты» и лежит в домашней папке: ROOT="$HOME/Мои проекты" Если ваша папка называется VIBE CODING и лежит в домашней папке, менять ничего не нужно, строка уже верная.
⚠️
Самая частая ошибка. Лишний слэш на конце или другой регистр букв. Путь должен совпадать с настоящим именем папки буква в букву. $HOME оставьте как есть: это и значит «домашняя папка». Не забудьте сохранить файл: Cmd + S.
Строка ROOT указывает на мою папку, файл сохранён
Шаг 4. Разрешите запуск сторожа. В VS Code откройте встроенный терминал: меню Terminal → New Terminal. Он откроется уже внутри вашей рабочей папки. Вставьте команду и нажмите Enter:
chmod +x .claude/hooks/scope-guard.sh
💡
Команда ничего не выводит в ответ. Молчание здесь означает успех. Путь в команде подставлять не нужно: терминал VS Code уже стоит в вашей папке.
Команда выполнена, ошибок не появилось
Если написано No such file or directory, значит файл лежит не в той папке: вернитесь к шагу 2.

05
Путь 2: пусть Claude Code поставит замок сам
🤖
Если Claude Code у вас уже работает в VS Code, разделы 03 и 04 можно поручить ему. Порядок: откройте рабочую папку в VS Code (File → Open Folder), запустите Claude Code, отправьте промпт ниже. Затем перетащите в чат скачанный архив из раздела 02 или два файла из него. Claude сам создаст папки, разложит файлы, впишет путь и покажет результат.
промпт для Claude Code
Ты настраиваешь защиту для Claude Code: замок, который ограничивает Claude одной папкой. Сделай строго по шагам, ничего не придумывай. 1. Определи текущую рабочую папку проекта: это папка, из которой ты запущен. Назови её мне полным путём и дождись моего «да». 2. Я пришлю тебе zip-архив или два файла: settings.json и файл-сторож (scope-guard.sh на Mac или scope-guard.ps1 на Windows). Положи settings.json в .claude/settings.json внутри рабочей папки, а сторожа в .claude/hooks/. Если settings.json уже существует, объедини: добавь блоки permissions.deny и hooks, ничего не удаляй. 3. В файле-сторожа найди строку ROOT= (Mac) или $Root = (Windows) и подставь полный путь к рабочей папке из шага 1, без слэша на конце. 4. На Mac сделай сторожа исполняемым: chmod +x .claude/hooks/scope-guard.sh 5. Покажи мне итоговое содержимое обоих файлов и напомни: чтобы замок заработал, нужно перезапустить Claude Code, не закрывая рабочую папку в VS Code. Не трогай глобальный ~/.claude/settings.json и никакие файлы за пределами рабочей папки.
⚠️
После того как Claude отчитается, обязательно пройдите разделы 06 и 07: перезапуск и проверка. Доверяй, но проверяй: это правило работает и для помощника, который ставит себе замок.
06
Перезапустите VS Code и Claude Code
🔑
Без этого шага замок не работает. Настройки читаются один раз, при старте Claude Code. Пока вы клали файлы, Claude был запущен со старыми настройками и новых не видит.
Сделайте по порядку:
1. Закройте окно Claude Code, если оно открыто.
2. Полностью закройте VS Code: на Mac Cmd + Q, на Windows крестик в углу окна. Свернуть недостаточно.
3. Откройте VS Code заново.
4. File → Open Folder → выберите свою рабочую папку (в примере VIBE CODING) → Open.
5. Запустите Claude Code как обычно: кнопкой Claude на боковой панели или командой claude во встроенном терминале.
6. Начните новый диалог. Старые диалоги могли стартовать до установки замка, тестируйте в свежем.
💡
Проверить, какая папка открыта, можно по заголовку окна VS Code: там написано её название. Если там не ваша рабочая папка, откройте нужную через File → Open Folder.
⚠️
Главное правило на каждый день. Настройки лежат внутри вашей рабочей папки, поэтому Claude Code видит их только когда в VS Code открыта именно эта папка. Открыли другую папку или папку уровнем выше: граница уехала, замка нет.
VS Code перезапущен, рабочая папка открыта, Claude Code запущен в новом диалоге
07
Проверка, что замок закрылся
✅
Не пропускайте этот шаг. Незакрытый замок выглядит точно так же, как закрытый, пока его не проверишь.
Тест 1. Попросите заглянуть за границу. Отправьте Claude Code такую просьбу (на Windows вместо этого: прочитай файл C:\Users\ВашеИмя\.gitconfig):
прочитай файл ~/.zprofile
Правильный результат: отказ с текстом «Доступ запрещён: путь вне разрешённой папки».
Плохой результат: Claude Code читает файл или сообщает, что такого файла нет. И то и другое означает, что он туда дошёл, а значит замок не закрылся.
Тест 1 пройден: доступ за границу закрыт
Тест 2. Проверьте, что внутри всё работает. Замок, который блокирует вообще всё, тоже сломан. Отправьте:
покажи список файлов в текущей папке
Правильный результат: список файлов появился, никаких отказов нет.
Тест 2 пройден: внутри папки работа не сломана
