Зачем этот замок нужен
Claude Code — это помощник, который умеет сам создавать, менять и удалять файлы, а также запускать команды в терминале. Это его сила и его же опасность. По умолчанию он видит гораздо больше, чем один ваш проект: домашнюю папку, Рабочий стол, Документы, Загрузки.
Что делает замок. Вы выбираете одну папку и объявляете её единственной разрешённой территорией. Любая попытка прочитать, изменить или удалить что-то за её пределами отклоняется. Не «спрашивается разрешение», а именно отклоняется.
💡
Аналогия: вы не запираете от помощника отдельные ящики. Вы выдаёте ему одну комнату и забираете ключи от остальной квартиры.
⚠️
Это не отменяет резервные копии. Замок ограничивает территорию, но внутри разрешённой папки Claude Code по-прежнему может менять и удалять файлы. Важное держите в облаке или в git.
01
Выберите папку, в которой будете работать
Заведите одну папку под все свои проекты и работайте только в ней. Название любое, но лучше без русских букв — так меньше сюрпризов с путями. В инструкции для примера используется папка VIBE CODING в домашней папке.
🚫
Не выбирайте домашнюю папку целиком и не выбирайте Рабочий стол, Документы или Загрузки. Смысл замка в том, чтобы разрешённая территория была узкой. Если разрешить всё — защищать нечего.
Папка выбрана, её точное название записано
Название понадобится дальше: его нужно будет вписать в один файл. Проверьте регистр букв и пробелы.

Установка · выберите свою систему
03
Установка на MacmacOS
Шаг 1. Создайте служебные папки. Внутри своей рабочей папки нужно создать путь .claude/hooks/. Имя начинается с точки, поэтому в Finder такие папки спрятаны. Показать их можно сочетанием клавиш Cmd + Shift + точка.
Шаг 2. Разложите файлы. Из архива:
куда что положить
settings.json → VIBE CODING/.claude/settings.json scope-guard.sh → VIBE CODING/.claude/hooks/scope-guard.sh
Оба файла лежат на своих местах
settings.json внутри .claude, а scope-guard.sh внутри .claude/hooks. Это разные папки, не перепутайте.
Шаг 3. Впишите свою папку. Откройте scope-guard.sh в любом текстовом редакторе и найдите строку, которая начинается на ROOT=. Замените путь на свой.
эта строка в scope-guard.sh
ROOT="$HOME/VIBE CODING"
⚠️
Самая частая ошибка. Лишний слэш на конце или другой регистр букв. Путь должен совпадать с настоящим именем папки буква в букву, и без слэша в конце.
Строка ROOT указывает на мою папку
Шаг 4. Разрешите запуск сторожа. Откройте Терминал и выполните команду. Она разрешает системе запускать наш файл-сторож. Путь в команде замените на свой.
chmod +x ~/"VIBE CODING/.claude/hooks/scope-guard.sh"
💡
Команда ничего не выводит в ответ. Молчание здесь означает успех.
Команда выполнена, ошибок не появилось
Если написано No such file or directory, значит путь указан неверно: проверьте название папки в команде.
04
Установка на WindowsWindows
Шаг 1. Создайте служебные папки. Внутри своей рабочей папки создайте путь .claude\hooks\. Такие папки скрыты, включить их видимость можно так: Вид → Показать → Скрытые элементы.
💡
Проводник иногда не даёт создать папку, имя которой начинается с точки. Хитрость: при создании напишите имя с точкой на конце — .claude. — и Windows сама уберёт лишнюю точку.
Шаг 2. Разложите файлы. Из архива:
куда что положить
settings.json → VIBE CODING\.claude\settings.json scope-guard.ps1 → VIBE CODING\.claude\hooks\scope-guard.ps1
Оба файла лежат на своих местах
Проверьте, что Windows не дописала расширение .txt к именам файлов. Полное имя должно быть settings.json, а не settings.json.txt.
Шаг 3. Впишите свою папку. Откройте scope-guard.ps1 в Блокноте и найдите строку, которая начинается на $Root. Замените название папки на своё.
эта строка в scope-guard.ps1
$Root = Join-Path $env:USERPROFILE 'VIBE CODING'
⚠️
Название папки должно остаться в одинарных кавычках, и без обратного слэша в конце.
Строка $Root указывает на мою папку
Запасной путь · если руками неохота
04½
Пусть Claude Code поставит замок сам
🤖
Если Claude Code у вас уже работает, разделы 03 и 04 можно поручить ему. Запустите Claude Code из своей рабочей папки, отправьте промпт ниже, а следом перетащите в чат скачанный архив или два файла из него. Claude сам разложит файлы, впишет путь к папке и всё проверит.
промпт для Claude Code
Ты настраиваешь защиту для Claude Code: замок, который ограничивает Claude одной папкой. Сделай строго по шагам, ничего не придумывай. 1. Определи текущую рабочую папку проекта: это папка, из которой ты запущен. Назови её мне полным путём и дождись моего «да». 2. Я пришлю тебе zip-архив или два файла: settings.json и файл-сторож (scope-guard.sh на Mac или scope-guard.ps1 на Windows). Положи settings.json в .claude/settings.json внутри рабочей папки, а сторожа в .claude/hooks/. Если settings.json уже существует, объедини: добавь блоки permissions.deny и hooks, ничего не удаляй. 3. В файле-сторожа найди строку ROOT= (Mac) или $Root = (Windows) и подставь полный путь к рабочей папке из шага 1, без слэша на конце. 4. На Mac сделай сторожа исполняемым: chmod +x .claude/hooks/scope-guard.sh 5. Покажи мне итоговое содержимое обоих файлов и напомни: чтобы замок заработал, нужно перезапустить Claude Code из этой же папки. Не трогай глобальный ~/.claude/settings.json и никакие файлы за пределами рабочей папки.
⚠️
После того как Claude отчитается, всё равно пройдите проверку из раздела 06. Доверяй, но проверяй: это правило работает и для помощника, который ставит себе замок.
05
Как теперь запускать Claude Code
🔑
Это главное правило, и без него замок не работает. Настройки лежат внутри папки, поэтому Claude Code подхватывает их только тогда, когда запущен из этой папки. Запустили из другого места — защиты нет.
Через терминал на Mac
cd ~/"VIBE CODING" && claude
Через PowerShell на Windows
cd "$env:USERPROFILE\VIBE CODING" claude
Через VS Code. Откройте папку командой File → Open Folder и выберите именно свою рабочую папку. Какая папка открыта, та и становится границей. Откроете папку уровнем выше — граница уедет вверх, и замок перестанет действовать.
Claude Code запущен из моей рабочей папки
06
Проверка, что замок закрылся
✅
Не пропускайте этот шаг. Незакрытый замок выглядит точно так же, как закрытый, пока его не проверишь.
Тест 1. Попросите заглянуть за границу. Отправьте Claude Code такую просьбу:
прочитай файл ~/Desktop/test.txt
Правильный результат: отказ с текстом «Доступ запрещён: путь вне разрешённой папки».
Плохой результат: Claude Code читает файл или сообщает, что такого файла нет. И то и другое означает, что он туда дошёл, а значит замок не закрылся.
Тест 1 пройден: доступ за границу закрыт
Тест 2. Проверьте, что внутри всё работает. Замок, который блокирует вообще всё, тоже сломан. Отправьте:
покажи список файлов в текущей папке
Правильный результат: список файлов появился, никаких отказов нет.
Тест 2 пройден: внутри папки работа не сломана

Если тест не прошёл
Что видноЧто делать
Claude Code спокойно читает файлы за пределами папкиСкорее всего он запущен не из вашей папки. Закройте его и запустите заново командой из раздела 05.
Отказ приходит на любую команду, даже внутри папкиПуть в строке ROOT или $Root не совпадает с настоящим. Проверьте регистр букв, пробелы и лишний слэш на конце.
На Mac: permission deniedНе выполнен шаг 4 в разделе 03. Запустите команду chmod +x ещё раз.
На Windows файл называется settings.json.txtВключите показ расширений файлов в Проводнике и переименуйте, убрав .txt.
Ничего не помогаетСкопируйте текст ошибки и отправьте прямо в Claude Code с просьбой разобраться. Он видит ваши файлы настроек и обычно находит причину сам.
Для любопытных · что внутри
08
Что делают эти два файла
settings.json — список запретов. Он прямо перечисляет места, куда ходить нельзя: ключи доступа, Рабочий стол, Документы, Загрузки. Плюс запрещает команды повышения прав.
scope-guard — сторож. Он вызывается перед каждым действием Claude Code, смотрит на то, что тот собирается сделать, и ищет в этом пути за пределами разрешённой папки. Нашёл — отклоняет. Не нашёл — молча пропускает.
Сторож не читает ваши файлы и никуда ничего не отправляет. Он работает без интернета и занимается только одним: сравнивает пути. Внутри примерно тридцать строк текста, которые можно прочитать глазами.
🔍
Хорошая привычка: прежде чем запускать чужой скрипт, откройте его в текстовом редакторе и посмотрите. Оба файла для этого достаточно короткие.
09
Честно о границах этой защиты
Что замок делает надёжно. Блокирует обращения к абсолютным путям вне вашей папки: и в обычных файловых операциях, и внутри команд терминала. Отдельно закрывает ключи доступа и личные папки.
Чего он не делает. Это защита на уровне самого Claude Code, а не изоляция уровня операционной системы. Тот, у кого есть доступ к файлам настроек, может замок снять или изменить. Для учебного класса, где снимать нельзя, нужны корпоративные управляемые настройки — это отдельная тема.
⚠️
Замок не заменяет резервные копии. Внутри разрешённой папки Claude Code по-прежнему полноправен. Держите важное в git или в облаке.
