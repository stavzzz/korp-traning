Зачем учиться читать документацию OpenClaw
🧭 За 5 уроков мы построили инфраструктуру, научили агента говорить, подключили n8n и Google. Теперь переход на новый уровень: учимся самостоятельно копаться в OpenClaw. Без этого навыка после интенсива упрёшься в потолок на первой же нестандартной задаче.

Проблема: документация OpenClaw — это 200+ страниц, и она обновляется каждый месяц. Читать её глазами — медленно и неэффективно.

Решение: отдать всю документацию Claude — и в claude.ai, и в Claude Code. Один раз настроил — и твои AI-ассистенты знают OpenClaw целиком, без галлюцинаций и устаревших ответов.

1. Документация (эта глава) — Claude понимает, как устроен OpenClaw. Учебник.
2. MCP OpenClaw (следующая глава) — Claude получает руки для работы с твоим инстансом.
Вместе — режим БОГА.

Что такое llms-full.txt и почему это именно то, что нам нужно
LLMS-FULL.TXT
Стандарт llmstxt.org — авторы проекта публикуют всю свою документацию в одном .md-файле, заточенном под загрузку в AI-инструменты (Claude, ChatGPT и т.п.).
📌 Пример: команда OpenClaw собрала все 200+ страниц документации в один текстовый файл ~4 МБ. Скачал → отдал Claude → Claude знает OpenClaw целиком. Никаких галлюцинаций, никаких устаревших ответов.

Размер файла — ~4 МБ (примерно 1 миллион токенов). Это огромный файл. Читать его целиком каждый раз Claude Code не будет (да и не сможет — даже Claude Opus 4.7 с контекстом в 1 млн токенов упрётся в потолок).

Поэтому в практике ниже мы попросим Claude Code разбить этот файл на тематические разделы. Так Claude будет подтягивать только нужные 5–15К токенов на каждый вопрос вместо 1 млн.

💎 «У меня же Claude Opus 4.7 с контекстом 1М токенов — зачем разбивать?»
— Скорость: 5–15К токенов раздела → ответ за секунды. 1 млн токенов целиком → минута ожидания каждый раз.
— Точность: Claude фокусируется на релевантном разделе — меньше шума, меньше ошибок.
— Стоимость: если работаешь через API — разбивка экономит десятки долларов в месяц.
— Переносимость: в Главе 03 подключим Claude Code в Telegram-бота на сервере, там может быть другая модель и лимиты. Разбитая дока работает везде.

Шаг 1. Скачиваем документацию локально на компьютер

Начинаем с локальной машины. Открой терминал:

— Mac: Terminal.app или iTerm
— Windows: PowerShell (встроенный, ищи через «Пуск» → PowerShell)

Важно: НЕ используй терминал VS Code, подключённый к серверу по SSH — нам нужен именно локальный терминал компьютера.

Скачать llms-full.txt в папку openclaw-docs/ в домашней директории
Команда ниже создаст папку openclaw-docs/ в твоей домашней директории и скачает туда всю документацию одним файлом (~4 МБ). Выбери команду для своей ОС.
🍎 Mac (Terminal / iTerm)
mkdir -p ~/openclaw-docs && curl -o ~/openclaw-docs/openclaw.md https://docs.openclaw.ai/llms-full.txt
🪟 Windows (PowerShell)
New-Item -ItemType Directory -Force -Path "$HOME\openclaw-docs" | Out-Null; Invoke-WebRequest -Uri "https://docs.openclaw.ai/llms-full.txt" -OutFile "$HOME\openclaw-docs\openclaw.md"
Проверить, что файл скачался
Выбери команду для своей ОС и проверь размер файла — должно быть ~4 МБ.
🍎 Mac (Terminal / iTerm)
ls -lh ~/openclaw-docs/openclaw.md
🪟 Windows (PowerShell)
Get-Item "$HOME\openclaw-docs\openclaw.md" | Select-Object Name, @{Name="Size(MB)";Expression={[math]::Round($_.Length/1MB,2)}}
✅ Если видишь файл размером примерно 4 МБ — всё ок. Файл лежит в папке openclaw-docs/ в твоей домашней директории.

Скопировать папку openclaw/ на сервер по SCP
Команда выполняется в локальном терминале компьютера (НЕ в терминале VS Code с Remote-SSH). Замени <IP> на IP-адрес твоего VPS. Замени путь в начале команды на полный путь к твоей папке OpenClaw. Выбери команду для своей ОС.

Для Windows: команда scp встроена в OpenSSH Client по умолчанию на Windows 10/11. Если её нет — включи «OpenSSH Client» в «Параметры → Приложения → Дополнительные компоненты».
🍎 Mac (Terminal / iTerm)
scp -r ~/путь/до/OpenClaw/openclaw root@<IP>:~/openclaw-docs/
🪟 Windows (PowerShell)
scp -r "$HOME\путь\до\OpenClaw\openclaw" root@<IP>:~/openclaw-docs/
Проверить, что папка появилась на сервере
Подключись к серверу одной командой — она работает одинаково на Mac и Windows.
ssh root@<IP> "ls -lh ~/openclaw-docs/openclaw/ | head -25"
✅ Если видишь список из 22 файлов (index.md + 21 тематический файл) — перенос прошёл успешно. Теперь документация лежит в двух местах: локально на компьютере и на сервере.

Шаг 1. Достаём Gateway-токен с сервера
🔑 Чтобы Claude Code мог подключиться к твоему OpenClaw Gateway, ему нужен токен авторизации. Этот токен лежит на сервере, где у тебя крутится OpenClaw — в файле ~/.openclaw/gateway.token. Сейчас его аккуратно достанем.
🛡️ Безопасность токена — критично:
— Не коммить токен в git
— Не публикуй в открытых чатах и не отправляй скриншоты с ним
— Если токен утёк — на сервере выполни openclaw security rotate чтобы создать новый
— Файл с токеном на компьютере держим только в ~/.openclaw/ (или аналогичной системной папке) — с правами доступа только для тебя
Подключиться к серверу и достать токен
Подключись к серверу через VS Code Remote-SSH (или обычным ssh в локальном терминале) и выполни команду ниже. На экран выведется длинная строка — это и есть токен. Скопируй его в буфер обмена.
ssh root@<IP> "cat ~/.openclaw/gateway.token"
Сохранить токен локально на компьютере
Создай папку ~/.openclaw/ у себя на компьютере и положи туда файл gateway.token с содержимым из предыдущего шага. Выбери команду для своей ОС.
🍎 Mac (Terminal / iTerm)
mkdir -p ~/.openclaw && echo 'ВСТАВЬ_СЮДА_ТОКЕН' > ~/.openclaw/gateway.token && chmod 600 ~/.openclaw/gateway.token
🪟 Windows (PowerShell)
New-Item -ItemType Directory -Force -Path "$HOME\.openclaw" | Out-Null; Set-Content -Path "$HOME\.openclaw\gateway.token" -Value 'ВСТАВЬ_СЮДА_ТОКЕН' -NoNewline
⚠️ В команде замени ВСТАВЬ_СЮДА_ТОКЕН на реальный токен, который ты получил в предыдущем шаге. После замены — выполни команду в терминале.

На Mac команда дополнительно ставит права 600 (читать может только владелец) — это правильный security-паттерн.
Проверить, что токен сохранился
Выбери команду для своей ОС — должно вывестись содержимое файла (твой токен).
🍎 Mac (Terminal / iTerm)
cat ~/.openclaw/gateway.token
🪟 Windows (PowerShell)
Get-Content "$HOME\.openclaw\gateway.token"

Шаг 5. Что такое Context7 и зачем он нужен
CONTEXT7
Бесплатный MCP-сервер от компании Upstash. По запросу Claude Code подтягивает актуальную документацию любых популярных библиотек (axios, telegraf, n8n, react, supabase и тысячи других).
📌 Зачем нужен: когда Claude Code пишет скиллы для OpenClaw или интеграции — он будет работать с актуальными API сторонних либ, а не с устаревшими данными из своего обучения. Это убирает галлюцинации в коде.
🛡️ Почему Context7 безопасный:
— Опенсорс на GitHub: github.com/upstash/context7
— Сама официальная документация OpenClaw упоминает Context7 как пример MCP-сервера — это лучшее подтверждение качества
— Лицензия MIT, миллионы загрузок в месяц
— Работает БЕЗ API-ключа (с бесплатными лимитами) или с ключом (повышенные лимиты)

Как Claude Code будет использовать Context7:

1. Ты пишешь промпт «напиши скилл для OpenClaw, который шлёт уведомления через node-telegraf»
2. Claude Code сам обращается к Context7: «дай мне актуальную доку по node-telegraf»
3. Context7 подтягивает свежую доку с официального сайта библиотеки
4. Claude Code пишет код с учётом актуальных API → код работает с первого раза

По официальной документации OpenClaw Context7 интегрируется как обычный stdio MCP-сервер — мы добавим его в тот же .mcp.json.

💡 Почему именно tmux + non-root юзер, а не Docker:
— В Claude Code 2.1.121+ Anthropic заблокировал ключевой флаг под root в Docker-контейнере (после публичного инцидента с rm -rf ~/)
— tmux вместо контейнера решает всё нативно: запускается под обычным shell, никаких блокировок, простой detach/attach
— Под non-root юзером никаких prompt'ов про bypass permissions не появляется — флаг разрешён по дизайну Anthropic
— Меньше движущихся частей = надёжнее на учебном сервере
🛡️ Важный нюанс безопасности. Юзер claude-bot формально не root, но через права на папку /root/.openclaw/ и членство в группе sudo он может управлять всем OpenClaw-окружением. Через Telegram-бота этот доступ становится мобильным. Поэтому критично:
1. Allowlist в Telegram — только твой аккаунт может писать боту (закрываем в Шаге 13)
2. Токен бота не утекает — храним в безопасном месте, не коммитим в git
3. Ротация при компрометации — если что-то утекло, BotFather перегенерирует токен за минуту

Шаг 2. Настраиваем SSH-конфиг на компьютере
🔌 В этой главе будем подключаться к серверу под двумя разными юзерами: root (для подготовки) и claude-bot (для основной работы). Чтобы каждый раз не вводить полные параметры — настроим ~/.ssh/config на компьютере.

Шаг 3. Создаём юзера claude-bot на сервере
👤 Под root запускать Claude Code в режиме автономной работы запрещено самим Anthropic. Поэтому создаём отдельного юзера claude-bot, добавляем его в группу sudo и в дальнейшем работаем под ним.
Подключиться к серверу под root через VS Code Remote-SSH
В VS Code: Cmd+Shift+P (Mac) / Ctrl+Shift+P (Windows) → Remote-SSH: Connect to Host → выбери openclaw-root. Открой Terminal в VS Code — он будет на сервере под root.
Создать юзера claude-bot и добавить в sudo
В терминале сервера (под root) выполни команду ниже. Команда passwd попросит задать пароль — придумай надёжный, сохрани в безопасное место.
useradd -m -s /bin/bash claude-bot && passwd claude-bot && usermod -aG sudo claude-bot
Разрешить SSH-вход новому юзеру по ключу
Скопируй авторизованные SSH-ключи root-а в домашнюю папку нового юзера, чтобы заходить по тому же ключу.
mkdir -p /home/claude-bot/.ssh && cp /root/.ssh/authorized_keys /home/claude-bot/.ssh/ && chown -R claude-bot:claude-bot /home/claude-bot/.ssh && chmod 700 /home/claude-bot/.ssh && chmod 600 /home/claude-bot/.ssh/authorized_keys
Проверить SSH-подключение под claude-bot
В локальном терминале на компьютере выполни команду — должен увидеть claude-bot.
ssh openclaw-bot "whoami"

Шаг 4. Даём юзеру claude-bot доступ к файлам OpenClaw-агента
🚨 Это нестандартная манипуляция, нужно понимать что делаем.

OpenClaw-агент работает как root-сервис. Его файлы (SOUL.md, MEMORY.md, скиллы, конфиг) лежат в /root/.openclaw/, и обычно туда не пускают никого кроме root.

Чтобы Claude Code-бот мог читать и редактировать эти файлы — мы передаём права на эту папку юзеру claude-bot. Сама папка остаётся в /root/, но её содержимое теперь принадлежит claude-bot.

OpenClaw-агент продолжит работать — root всегда имеет доступ к любым файлам независимо от owner-а.
Передать владение /root/.openclaw/ юзеру claude-bot
В терминале сервера под root. После выполнения папка останется в /root/, но все файлы внутри будут принадлежать claude-bot.
chown -R claude-bot:claude-bot /root/.openclaw/
Проверить, что владелец сменился
Должен увидеть claude-bot claude-bot рядом с .openclaw.
ls -la /root/ | grep openclaw
✅ Готово. Теперь юзер claude-bot может полностью читать и править файлы OpenClaw-агента, а сам агент продолжает работать без перебоев.

Шаг 15. Настраиваем автозапуск tmux-сессии при reboot сервера
🚨 ОБЯЗАТЕЛЬНЫЙ ШАГ — НЕ ПРОПУСКАЙ.

Без этого шага:

1. После reboot сервера бот умрёт. tmux-сессия живёт только в RAM — после перезагрузки её надо запускать заново. Ты можешь не заметить этого до первого падения сервера или планового обновления Ubuntu.

2. Многие шаги в следующих главах ломаются. В частности, в Части 2 Главе 02 при правке AGENTS.md или OpenClaw-агента может потребоваться рестарт через systemd. Если юнита нет — бот в Telegram даст ошибку «Unit claude-bot.service not found», и ты застрянешь.

3. Любая инструкция курса с systemctl restart claude-bot работает только если этот шаг сделан.

Если ты сейчас проходишь курс впервые — сделай этот шаг обязательно прямо сейчас, до перехода в следующую главу.

Решаем через systemd-сервис, который автоматически создаёт tmux-сессию при старте сервера.
Создать systemd-юнит для автозапуска tmux-сессии
Команда требует sudo. Создаст файл /etc/systemd/system/claude-bot.service с настройкой автозапуска.
sudo tee /etc/systemd/system/claude-bot.service > /dev/null << 'EOF' [Unit] Description=Claude Code Telegram Bot (tmux session) After=network.target [Service] Type=forking User=claude-bot Environment=PATH=/home/claude-bot/.npm-global/bin:/home/claude-bot/.bun/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin ExecStart=/usr/bin/tmux new-session -d -s claude-bot 'cd /home/claude-bot/claude-code-bot/OpenClaw && /home/claude-bot/.npm-global/bin/claude --channels plugin:telegram@claude-plugins-official --dangerously-skip-permissions' ExecStop=/usr/bin/tmux kill-session -t claude-bot Restart=on-failure RestartSec=10 [Install] WantedBy=multi-user.target EOF
Включить автозапуск сервиса
Сначала останавливаем текущую tmux-сессию (если запущена), потом включаем сервис, потом стартуем через systemd.
tmux kill-session -t claude-bot 2>/dev/null; sudo systemctl daemon-reload && sudo systemctl enable claude-bot.service && sudo systemctl start claude-bot.service && sudo systemctl status claude-bot.service
✅ Если в выводе видишь Active: active (running) — сервис настроен. Теперь после любого reboot сервера бот в Telegram автоматически вернётся в работу за 10-30 секунд.

Шаг 2. Создаём vault со структурой папок
📁 Vault — это просто папка на твоём компьютере. Внутри будут подпапки по правилам Карпати: raw/ (сырые материалы), wiki/ (обработанные знания), daily/ (ежедневные заметки), outputs/ (результаты работы агентов).
Создать vault через Obsidian → Create new vault
Открой Obsidian → Create new vault. Имя — например second-brain. Расположение — где удобно (например, ~/Documents/second-brain). Нажми Create. Vault создан.
Создать внутри vault 4 подпапки: raw, wiki, daily, outputs
В Obsidian слева — правый клик по vault → New folder. Создай поочерёдно: raw, wiki, daily, outputs.
Создать файл .gitkeep в каждой из 4 папок (raw, wiki, daily, outputs)
⚠️ Важно — иначе все следующие шаги сломаются. Git не отслеживает пустые папки. Если папки пустые — они не уедут на GitHub при первом push, и агенты на сервере получат vault без структуры.

Решение: в каждой из 4 папок создаём пустой служебный файл .gitkeep. Это стандартная практика — точка в начале делает файл скрытым, он не мешается, но фиксирует папку в git.

Как сделать через Obsidian:
1. В левой панели Obsidian → правый клик по папке raw → New note
2. Имя файла введи точно так: .gitkeep (с точкой в начале, без .md)
3. Когда Obsidian спросит «создать файл без расширения?» — соглашайся
4. Файл создан, ничего внутрь не пиши
5. Повтори для папок wiki, daily, outputs

Альтернатива через терминал (если правый клик не работает или Obsidian не даёт создать файл с точкой):
cd ~/Documents/second-brain && touch raw/.gitkeep wiki/.gitkeep daily/.gitkeep outputs/.gitkeep
✅ После выполнения — в каждой из 4 папок есть скрытый файл .gitkeep. Структура зафиксирована, при первом push в Шаге 6 все папки уедут на GitHub.
Создать в корне vault файл INDEX.md
Правый клик по корню vault → New note → имя INDEX. Внутрь пока ничего не пиши — это будет «оглавление» твоих знаний, агенты сами начнут его наполнять.

Шаг 7. Настраиваем автоматическую синхронизацию в плагине Git
⚙️ В новых версиях плагина настройки идут одним длинным списком — нет отдельных секций «Backup» / «Pull». Просто прокручивай настройки сверху вниз и находи нужные пункты.
Включить автоматическую синхронизацию в плагине Git
1. Открой настройки плагина: Settings (⚙️ внизу слева) → в левом меню найди Git (в разделе «Community plugins») → кликни.

2. Найди секцию Automatic (в самом верху). В ней:
— Auto commit-and-sync interval (minutes) → впиши 5. Это главное поле — каждые 5 минут плагин будет автоматически делать commit + pull + push одним действием.
— Auto pull interval (minutes) → впиши 5. Каждые 5 минут будет тянуть свежие изменения с сервера.
— Auto commit-and-sync after stopping file edits → включи тумблер. Автокоммит сработает только когда ты перестанешь печатать. Без этого плагин может коммитить прямо во время набора — раздражает.

3. Прокрути ниже до секции Commit-and-sync. Там убедись, что включены:
— Push on commit-and-sync → должно быть ON (по умолчанию включено)
— Pull on commit-and-sync → должно быть ON (по умолчанию включено)
Это значит, что одно действие «commit-and-sync» делает сразу commit → pull → push. Поэтому отдельное Auto push interval тебе НЕ нужно — оставь его 0.

4. Закрой настройки — они сохраняются автоматически.
⚠️ ВАЖНО: в старых гайдах поле называлось Vault backup interval. В новых версиях его переименовали в Auto commit-and-sync interval. Это то же самое поле — просто новое название.
Проверка: убедиться, что автосинхронизация реально работает
Прежде чем идти на сервер — проверим, что плагин действительно пушит на GitHub.

3. Открой свой репо на GitHub → вкладка Commits (https://github.com/<твой-username>/second-brain/commits/main).

4. Должен появиться новый коммит с сообщением вида:

(либо твоё кастомное сообщение, если меняли в настройках).

5. Кликни по этому коммиту → убедись, что внутри есть твоя правка INDEX.md.
✅ Если коммит на GitHub появился — двусторонняя синхронизация работает. Идём дальше к Шагу 8 (серверная сторона).
⚠️ Если коммита нет — варианты:
