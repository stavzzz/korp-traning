01
Новые термины урока
📖 Теоретический блок — смотрим вместе с видео. Ключевые понятия урока 7.
Control UI (веб-панель OpenClaw)
Встроенная веб-панель управления агентами — открывается командой openclaw dashboard. Чат с агентами плюс управление агентами, скиллами и каналами.
📌 Это «пульт» вашего офиса из урока 3. С него и начнём.
Gather
Сервис 2D-пиксельного виртуального офиса с аватарами (как в игре). Мы используем его, чтобы наглядно «поселить» туда своих агентов.
📌 gather.town. Каждый агент станет персонажем за столом.
Мост (bridge)
Небольшой Node-скрипт, который связывает два мира: читает статусы агентов у OpenClaw и отражает их на аватарах в Gather. У OpenClaw нет аватаров, у Gather нет ИИ — мост соединяет их.
📌 Именно его мы напишем вайб-кодингом в секции 04.
Gateway
«Сервер» OpenClaw, к которому подключаются и веб-панель, и наш мост. Доступ — по токену с нужными правами.
📌 Локально живёт на ws://127.0.0.1:18789. Наружу не выставляем.
gather-game-client
Официальный SDK Gather (WebSocket), которым программно «водят» аватаров: сажают за стол, показывают статус-пузыри, двигают.
📌 npm-пакет @gathertown/gather-game-client. Его поставит и использует наш мост.

03
Зачем визуализация и как устроен мост

Проблема: когда агентов становится много, держать в голове «кто чем сейчас занят» невозможно.

Решение: наглядная карта офиса, где каждый агент — персонаж, а его статус видно в реальном времени.

Вы ──▶ Telegram ──▶ OpenClaw (агенты, суб-агенты) │ │ Gateway WebSocket │ события: кто сейчас работает ▼ ┌──────────────┐ │ МОСТ │ Node-скрипт (office-bridge) └──────┬───────┘ │ gather-game-client (WebSocket) ▼ Gather — пиксельный офис: аватары + статусы

Что делает что:

— OpenClaw — мозги и агенты (уже собраны).
— Мост — читает у gateway, кто из агентов сейчас работает / зовёт инструмент / закончил.
— Gather — рисует это на аватарах: статус-пузырь над «столом» агента.

🎯 Важно: нативной интеграции OpenClaw ↔ Gather нет — мост мы пишем сами. Это несложно и полностью в духе курса.
04
Подготовка Gather
🏢 Готовим пространство-офис и достаём три вещи, которые понадобятся мосту: API-ключ, ID пространства и ID карты.
Создать пространство-офис в Gather
Из готового шаблона офиса. Расставьте «столы» (объекты) под ваши роли агентов.
Получить API-ключ
На странице gather.town/apiKeys. Сохраните в менеджер паролей.
Взять SPACE_ID из URL пространства
Формат вида 5jnhRfDYRIUyDmbF/my-space. В коде слэш меняется на бэкслеш.
Взять MAP_ID
Из панели Rooms в редакторе карт (Mapmaker).
Записать, за каким столом сидит какой агент
Понадобится для маппинга «агент → персонаж на карте» в мосте.
🔎 Официальные доки для справки: Gather API.
05
Пишем мост OpenClaw ↔ Gather
🚀 Всю работу делает Claude Code. Открываем VS Code с подключением к серверу и собираем мост одним промптом, дальше правим по ходу.
Открыть VS Code с подключением к серверу (как в уроке 3)
Remote-SSH к VPS, «Режим бога» в Claude Code включён.
Отправить Claude Code промпт ниже
Замените плейсхолдеры в .env на свои значения перед запуском. Ключи и токен — только в .env, не в коде.
📋 Промпт: собрать мост office-bridge
Собери Node-сервис office-bridge, который связывает мой OpenClaw с пиксельным офисом Gather: 1. Подключись к моему OpenClaw gateway по ws://127.0.0.1:18789 с операторским токеном (scope operator.read). Токен возьми из .env (GATEWAY_TOKEN). Вызови метод agents.list, затем подпишись через sessions.subscribe и sessions.messages.subscribe. 2. Подключись к Gather через пакет @gathertown/gather-game-client (класс Game + connect). Не забудь global.WebSocket = require("isomorphic-ws"). GATHER_API_KEY, GATHER_SPACE_ID и GATHER_MAP_ID возьми из .env. 3. Маппинг "agentId -> объект-персонаж на карте Gather" возьми из config.json. 4. На события session.operation / session.tool / sessions.changed меняй статус-пузырь над объектом соответствующего агента через engine.sendAction({ $case: "mapSetObjects", ... }): - идёт прогон -> "работает" - вызов инструмента -> "ищет в вебе" / "пишет" / по имени инструмента - закончил -> "готово" - ждёт подтверждения -> "ждёт подтверждения" 5. Все секреты только в .env, не хардкодь. Мосту нужен доступ только на чтение. В конце выведи: путь к созданным файлам и команду запуска.
Заполнить config.json: агент → персонаж на карте
Сопоставьте id каждого агента с объектом-столом в Gather (из секции 04).
Заполнить .env: токен gateway + ключ и ID Gather
GATEWAY_TOKEN, GATHER_API_KEY, GATHER_SPACE_ID, GATHER_MAP_ID.
💡 Начинаем с простого варианта — статус-пузыри над столами. Живые «ходячие» аватары можно добавить позже — логика та же.

07
Безопасность
🚨 API-ключ Gather и токен gateway = доступ к вашей системе. Обращайтесь с ними как с паролями.
Ключи и токен — только в .env, никогда не в коде и не на экране
Не коммитьте .env в git и не показывайте на записи/стриме.
Мосту дать доступ только на чтение
Для статус-пузырей достаточно operator.read — прав записи не давайте.
Gateway не выставлять в интернет
Мост держите на том же сервере; наружу смотрит только сам Gather.
