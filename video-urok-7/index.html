01
Новые термины урока
📖 Теоретический блок — смотрим вместе с видео. Ключевые понятия урока 7.
Control UI (веб-панель OpenClaw)
Встроенная веб-панель управления агентами — открывается командой openclaw dashboard. Чат с агентами плюс управление агентами, скиллами и каналами.
📌 Это «пульт» вашего офиса из урока 3. С него и начнём.
Gateway
«Сервер» OpenClaw, к которому подключаются и веб-панель, и наш мост. Доступ — по токену с нужными правами.
📌 Локально живёт на ws://127.0.0.1:18789. Наружу его не выставляем.
Мост (сервис данных)
Небольшой Node-скрипт: читает статусы агентов у gateway (только на чтение) и отдаёт их сайту. У OpenClaw нет наглядной карты, у сайта нет доступа к агентам — мост соединяет их.
📌 Именно его мы напишем вайб-кодингом в секции 05.
Тайлсет / спрайт
Набор пиксельных «плиток» (мебель) и «персонажей» из купленных ассетов. Формат — PNG на сетке, обычно 32×32 пикселя.
📌 Из тайлов собирается фон офиса, из спрайтов-персонажей — аватары агентов.
Tiled
Бесплатный редактор карт: из тайлов мышкой собирают комнату и экспортируют в картинку. Можно собрать карту и программно — Tiled не обязателен, но удобен для ручной доводки.
📌 mapeditor.org. «Симс для взрослых»: расставляете мебель по вкусу.
Caddy
Веб-сервер, который сам выпускает и продлевает бесплатный TLS-сертификат (Let's Encrypt). Через него сайт открывается по https на вашем домене.
📌 Наружу смотрит только Caddy. Сам gateway остаётся на loopback.

03
Архитектура: как данные летят на сайт

Проблема: когда агентов становится много, держать в голове «кто чем сейчас занят» невозможно.

Решение: наглядная карта офиса, где каждый агент — персонаж, а его статус виден в реальном времени.

Вы ──▶ Telegram / Control UI ──▶ OpenClaw (агенты, суб-агенты) │ │ Gateway WebSocket (operator.read) │ события: кто работает / зовёт инструмент / закончил ▼ ┌──────────────────┐ │ СЕРВИС-МОСТ │ Node: читает gateway, │ (на том же VPS) │ держит статусы, раздаёт сайт + WS └────────┬─────────┘ │ WebSocket (в браузер) ▼ Сайт на домене (Caddy + TLS + вход) пиксельный офис: аватары + подписи-статусы

Что делает что:

— OpenClaw — мозги и агенты (уже собраны).
— Сервис-мост — читает у gateway, кто из агентов сейчас работает, держит статусы, раздаёт сайт и шлёт обновления в браузер по WebSocket.
— Сайт — рисует офис и агентов, над каждым имя и статус, обновляется вживую.

🎯 Важно: нативной интеграции OpenClaw ↔ «красивый сайт» нет — весь мост мы пишем сами. Это несложно и полностью в духе курса.
04
Развилка: Gather или свой офис

Есть две дороги. Gather — готовый сервис 2D-офисов, отлично подходит для живых команд из людей. Свой офис — пиксельная карта на вашем домене, куда мы сажаем именно агентов. Ниже честно про обе, чтобы вы выбрали осознанно.

Вариант A — Gather (для команд из людей)

🧑‍🤝‍🧑 Gather хорош, когда офис нужен людям: созвоны, присутствие, спонтанные разговоры у виртуального кулера. Люди заходят аватарами, созваниваются по близости, «гуляют» по офису. Для этого он и создан — держите его в уме как рекомендацию для человеческих команд.
🛠️ Грабли Gather, если всё же пробуете его с API

1. Версии 2.0 и 1.0. API и SDK (gather-game-client) работают только с классическим Gather 1.0. Пространство создавать через app.gather.town/create (Start from blank или шаблон офиса). Офис, собранный в новом Gather 2.0, к API не подключить.

2. API-ключ. Со страницы ключей копируйте короткий ключ, который показывают один раз (~16 символов), а не длинную «encoded»-строку. Иначе будет ошибка Unauthorized: no uid found.

3. Идентификаторы. SPACE_ID из URL вида XXXX/имя-офиса (в коде слэш меняется на бэкслеш). MAP_ID — из вкладки Rooms в Mapmaker (Customize → Open Mapmaker).

4. SDK-нюансы. Метод mapSetObjects устарел, нужен mapSetObjectsV2. Без вызова game.enter({}) сервер молча игнорирует правки карты. setObject при промахе создаёт дубликат — менять объекты только через updateObject по ключу.

5. Статусы не висят постоянно. Подпись у объекта показывается только когда игрок рядом. Для «всегда видно» пришлось бы городить объект-заметку, и всё равно это не полноценный ярлык над головой.

🔴 Если хотите посадить в Gather именно АГЕНТОВ отдельными аватарами — так не выйдет удобно. Один API-ключ пускает бота под аккаунтом-владельцем (переименует вас) и даёт ровно одного персонажа. Для 11 агентов нужно 11 отдельных аккаунтов Gather = 11 почт = 11 ключей. Плюс на бесплатном тарифе лимит 10 одновременных участников. Это муторно и не масштабируется — поэтому основной путь урока другой.

Вариант B — свой пиксельный офис (основной путь, для агентов)

5.1 · Персонажи (аватары агентов)

Нарезать аватары агентов из купленных спрайтов
Claude Code распакует пак, вырежет по одному кадру на персонажа и разложит контактным листом, чтобы вы выбрали, кто есть кто.
📋 Промпт: нарезать персонажей
Распакуй купленный Modern Interiors. В 2_Characters/Character_Generator/0_Premade_Characters/32x32 лежат готовые персонажи (спрайт-листы). Мне нужны статичные аватары для агентов. Вырежи из каждого спрайт-листа ОДИН кадр в нужном ракурсе и сохрани отдельными PNG. Разложи 20 персонажей контактным листом с номерами, чтобы я выбрал, кто есть кто.
🔴 Грабли с ракурсом персонажа (важно, чтобы не вышел «затылок»)

В спрайт-листе первая полоса — «легенда» из 4 направлений. Столбец 0 — профиль (влево), столбец 1 — спина (лицом вверх, к монитору), столбец 3 — анфас (лицом к зрителю). Плюс вертикальное смещение примерно +16px: если резать с y=0, обрежется голова.

Для офиса, где столы монитором вверх и агент сидит спиной к зрителю, нужен столбец 1 (спина) — голова красиво торчит над спинкой кресла. Если стол развёрнут к зрителю — берите столбец 3 (анфас).

Кроп кадра, который сработал: (столбец*32, 16, столбец*32+32, 64).

💡 На маке системный Python для работы с картинками (Pillow) заблокирован. Claude Code должен ставить Pillow в venv, а не в систему — напомните ему об этом, если споткнётся.

Собрать фон офиса и координаты кресел
Два способа: программно (кодом из тайлов) или мышкой в Tiled. На выходе — PNG фона и layout.json с координатами каждого кресла.
📋 Промпт: собрать фон офиса
Собери фон офиса из ассетов Modern Office: пол, стены, N столов с мониторами по зонам (опенспейс + переговорки/кабинеты). Кресло у каждого стола. Выведи PNG фона и layout.json с координатами кресла для каждого места. Сделай на 15 мест с запасом.

5.3 · Рендер-сайт (страница офиса)

Сделать одностраничный сайт офиса
Обычная HTML-страница с <canvas> (движок вроде Phaser для статичной карты не нужен): грузит фон и аватары, сажает агентов по координатам, рисует над каждым имя и статус, слушает мост по WebSocket.
📋 Промпт: рендер-сайт офиса
Сделай одностраничный сайт: canvas грузит office_bg.png и аватары из layout.json, сажает каждого агента на его кресло так, чтобы голова торчала над спинкой (показывай верхние ~24px спрайта). Над агентом — две плашки: имя с эмодзи роли (тёмная) и статус (цветная, с эмодзи). Статусы читай по WebSocket с /ws. Лёгкая анимация покачивания, когда агент не отдыхает.

5.4 · Мост данных (сервис к gateway)

Написать сервис-мост к gateway
Подключается к gateway по WebSocket, читает статусы (только чтение), держит их в памяти, раздаёт сайт и вещает обновления браузеру по /ws. Токен — только в .env.
📋 Промпт: сервис-мост
Напиши Node-сервис: подключись к OpenClaw gateway ws://127.0.0.1:18789 с operator.read токеном из .env. Веди статус каждого агента. Раздавай статический сайт и WebSocket /ws с обновлениями статусов. Токен только в .env.
🔴 Грабли подключения к gateway (иначе не пустит)

В хендшейке connect поле client.id должно быть gateway-client, а client.mode — backend. Тогда на loopback gateway пускает без device-пейринга. Протокол 4, роль operator, scopes ["operator.read"].

Реальные события статусов: session.message (поля agentId, status: running|done), поток agent (stream: lifecycle|tool). agentId можно достать из sessionKey вида agent:<id>:<канал> (берётся второй сегмент).

🛠️ Gateway помечает running → done за доли секунды, и «работает» мелькает так, что не прочитать. Решение: держать статус «работает» минимум ~4 секунды, «готово» показывать короткой вспышкой ~3.5с, потом «отдыхает».

5.5 · Рассадка: агент → аватар → место

Заполнить layout.json: кто где сидит
layout.json связывает agentId (точный id из openclaw agents, не русское имя) → спрайт → координаты кресла → эмодзи роли. Агентов различаем по цвету причёски и подписи: со спины лицо не видно, идентифицирует ярлык.

Деплой на свой домен
🌐 Выкладываем офис так, чтобы он открывался по https на вашем домене и был закрыт входом. Наружу смотрит только Caddy — сам gateway остаётся на loopback.

7.1 · Домен и DNS

Направить домен на IP сервера (A-запись)
Купите домен или поддомен у любого регистратора. Добавьте A-запись: имя поддомена → IP вашего VPS. Проверьте, что резолвится: dig +short <домен> должен вернуть IP сервера.

7.2 · Веб-сервер и TLS (Caddy)

Поставить Caddy и настроить reverse-proxy на сервис
Caddy сам выпустит и продлит бесплатный сертификат Let's Encrypt.
📋 Промпт: Caddy + TLS
Открой в ufw порты 80 и 443. Поставь Caddy (статичный бинарник). Настрой Caddyfile: домен <домен> -> reverse_proxy на 127.0.0.1:<порт сервиса>. Подними Caddy как systemd-сервис.
🎯 Gateway наружу не выставляем. Наружу смотрит только Caddy (порты 80/443), он проксирует на локальный сервис-мост. Сам gateway остаётся на loopback.

7.3 · Вход (авторизация)

Сделать свою страницу входа в офис
Дефолтный basic_auth Caddy показывает уродливый браузерный попап — для демонстрации плохо. Делаем свою форму входа на уровне сайта: логин, пароль, кнопки «Войти» и «Выйти».
📋 Промпт: своя форма входа
Сделай на сайте свою страницу входа в пиксельном стиле (логин = моя почта, сложный пароль). Пароль сгенерируй на сервере и положи в файл с правами 600 — в чат/лог не выводи. Сессия — подписанная httpOnly cookie. Защити офис и WebSocket: без входа — редирект на форму. Добавь кнопку «Выйти» и пиксельный favicon.
🔴 Пароль генерируйте на сервере, кладите в файл с правами chmod 600 и никогда не печатайте в чат, лог или на экран. Забираете его сами с сервера. Секреты — только в .env и защищённых файлах, не в коде и не в git.
08
Безопасность и траблшутинг
🚨 API-ключи, токен gateway и пароль входа = доступ к вашей системе. Обращайтесь с ними как с паролями.
Мосту — доступ только на чтение
Для статусов достаточно operator.read. Прав записи не давайте.
Gateway не выставлять в интернет
Только loopback. Наружу смотрит Caddy, он проксирует на локальный сервис.
Секреты — только в .env и защищённых файлах

Сайт держать под паролем
Даже если «там только имена и статусы» — своя форма входа обязательна.
🔴 Готовый чужой проект openclaw-virtual-office — не ставить «из коробки». Аудит выявил критичное: (1) docker compose up по умолчанию поднимает Cloudflare-туннель и публикует всё в интернет без пароля; (2) в контейнер монтируется весь ~/.openclaw с токенами и ключами; (3) часть API публична, через неё можно запускать ваших агентов снаружи; (4) тянутся чужие образы :latest. Вредоноса в коде нет, но конфигурация опасна. Вывод: собирать своё (путь урока) или серьёзно допиливать чужое — это отдельная работа.
🛠️ Траблшутинг: что проверять, если не работает

1. Мост не подключается к gateway. Проверьте client.id=gateway-client, mode=backend, scope operator.read и токен в .env.

2. Статусы не приходят на сайт. Открыт ли WebSocket /ws, проксирует ли его Caddy, авторизован ли браузер (cookie).

3. Персонаж «затылком» или «в профиль». Неверный столбец кадра (для спины нужен столбец 1) или забыт вертикальный сдвиг +16px.

4. TLS не выпускается. Открыты ли порты 80 и 443 в ufw, резолвится ли домен на IP сервера.

5. Статус мелькает и не читается. Добавьте минимальное время показа «работает» (~4 секунды).

Что дальше: развитие офиса
🎨 Базовый офис работает как витрина только на чтение. Дальше его можно наращивать — по одной фиче, от простого к сложному.

Панель агента (дашборд). Клик по агенту → сбоку панель: его файлы, подключённые MCP, разрешённые инструменты, модель, расход токенов. Данные из gateway на чтение (agents.list, agents.workspace.list, sessions.usage).

Чат с каждым агентом. Окно диалога с конкретным агентом прямо на сайте. Это уже запись в gateway → отдельный scope и отдельный аудит: писать в агентов может только авторизованный владелец.

Кроны и автоматизации. Показывать расписание задач агента, ближайшие запуски, кнопку «запустить сейчас».

Живые «ходячие» аватары. Персонажи не сидят, а ходят по офису и собираются в переговорке на «совещание». Следующий уровень анимации.

Кастомная карта в Tiled и мультиофисы. Уникальный офис под свою команду, зоны под роли, несколько этажей и проектов с переключением.

🔴 Как только на сайте появляется запись (чат с агентом, запуск задач, правка конфигов) — это уже не «витрина», а пульт управления. Каждую такую фичу закрывайте авторизацией и проходите аудит: кто и что может делать. Витрину и пульт держите раздельно.
💡 Куда двигаться дальше:
• Добавляйте новых сотрудников в офис по одному, под конкретную задачу, которая реально болит.
• Раз в месяц пересматривайте, что из автоматизаций приносит пользу, а что можно выключить.
• Делитесь находками в чате потока — чужие связки часто подсказывают идеи для своих.
